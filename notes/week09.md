## 這週在講什麼
Vibe Coding 是「叫 AI 把這一個網頁做出來」；這週更進一步：**把專案的規則寫成一份文件**，之後不管哪個 AI 來接手，讀完文件就知道要怎麼繼續做。

## 1. AGENTS.md 和 CLAUDE.md 是什麼
- 放在專案最上層的 Markdown 文件，寫給 **AI 看的專案說明書**
- `AGENTS.md`：多數 AI 寫程式工具都會讀的通用名稱
- `CLAUDE.md`：Claude Code 會自動讀的名稱
- 兩個都想支援時，可以只寫一份 AGENTS.md，CLAUDE.md 裡寫「請讀 AGENTS.md」

## 2. 一份好的規則文件要寫什麼
| 項目 | 例子（以這個筆記網站為例） |
|---|---|
| 專案目的 | 整理每週上課重點，給初學者看 |
| 網頁風格 | 白底、深藍主色、白話、不用艱深術語 |
| 頁面結構 | 首頁卡片 + 側欄週次 + 內容區 |
| 新增內容的格式 | 每週一個 Markdown，照 `_template.md` 的段落順序 |
| 檔案命名與位置 | `notes/week兩位數.md`，並在 `notes/index.json` 加一筆 |
| AI 要遵守的規則 | 不改共用的版面檔、不放個資與 API 金鑰 |

## 3. 為什麼要寫成規則
- **每次都要重講需求很累**：規則寫一次，之後只要說「新增第 10 週」
- **AI 每次做出來的風格不一樣**：規則固定格式，頁面才會一致
- **換工具也能用**：規則是普通文字檔，不綁定任何一個 AI

## 本週作業
- 題目：建立自己的 AGENTS.md 或 CLAUDE.md，並用它做出網站
- 我的作品：就是這個筆記網站

---

## 本週三大重點
1. **AGENTS.md 是寫給 AI 的專案說明書**，放在專案最上層。
2. **規則要具體**：檔名、位置、段落順序都寫清楚，AI 才不會自己亂發揮。
3. **好的規則可以重複用**：新增內容時只要一句話，AI 就能照同一套方式完成。
